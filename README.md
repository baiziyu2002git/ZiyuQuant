# ZiyuQuant / 子瑜量研

> 一个围绕个人研究流程构建的、本地运行的 A 股日频量化研究工作台。

ZiyuQuant 是我给自己做的一套研究工具。它不试图把量化研究包装成一个“点一下就能赚钱”的黑盒，也不是一个为了展示指标而搭起来的网页。更具体地说，我希望它能把一条研究链路里最容易断开的部分放回同一个上下文里：因子到底怎么定义、当时能看到什么数据、策略如何把信号变成订单、订单为何成交或未成交、净值波动最后又落在哪些持仓上。

这个仓库是 ZiyuQuant 的公开展示页，记录产品界面、研究方法和我在实现过程中的一些取舍。它不是开源发布页，也没有下载、安装或在线体验入口。

**This repository is a product and research showcase only. Source code, datasets and application binaries are not distributed.**

## 展示范围：这里有什么、没有什么

这里展示的是一个真实本地研究环境中的界面与流程，包括因子研究、策略回测、模拟验证、模型研究、市场情绪、数据中心和运行历史。截图中可以看到研究脚本、结果表、曲线和操作状态，是为了让研究逻辑与研究结果能被一起理解；它们不等同于工程源码交付，也不附带可下载代码、数据或使用授权。

这个仓库**不提供**以下内容：

- 项目源代码、完整工程结构、私有策略包或可执行二进制；
- 原始行情、财务、公司事件、动态成分、账户、订单或数据库文件；
- 安装包、云端服务、账号、API、券商接口或任何实盘交易能力；
- 可据此复现实盘收益的参数、环境、数据版本或运行条件。

图中的回测、模拟账户、因子指标与模型界面均为本地研究展示。它们不是实盘业绩，不构成投资建议，也不应被理解为对未来收益、交易执行或数据完整性的承诺。

## 我想解决的，不只是画出一条净值线

最初做研究时，我也会先看最终收益、夏普或一条净值曲线。但研究做得稍微久一点，就会发现真正难解释的往往不是曲线本身，而是曲线背后的时间和账户逻辑：

- 一个因子使用的是当日收盘后才能知道的数据，还是交易前已经可见的数据？
- 信号生成以后，是当日成交、下一交易日成交，还是因为涨跌停、停牌、现金不足或整手约束而没有成交？
- 研究中的连续价格、账户中的成交价格、持仓估值和公司行为，是否被混成了一套看似方便但难以复核的口径？
- 当一段回测出现回撤，或一次模拟账户表现异常时，能否从净值一路查回到订单、成交、持仓和当时的输入？

ZiyuQuant 目前只聚焦 A 股日频研究，但希望把上述问题留在同一条工作流中：

`因子定义 → 单因子验证 → 策略脚本 → 回测净值 → 模拟预下单 → 正式订单与持仓 → 历史结果核对`

它不会替用户判断某个因子是否“必然有效”，也不会把研究过程伪装成无摩擦的自动交易。它更像一张研究台：把每一个本来容易被忽略的约束摊开，让自己在几周或几个月后回看时，仍然能知道一项结果大致是怎样得来的。

## 1. 因子研究：先知道因子在说什么，再看它是否有用

### 一页中看到研究结果，而不只看到一个均值

![主工作台：因子研究](media/01-主工作台-因子研究.png)

因子研究页把 IC、Rank IC、分层表现、预处理和分阶段结果放在同一个研究视图里。对我而言，单独写下“平均 IC 为正”信息量太少：它可能只来自一小段行情，也可能在不同阶段有完全不同的表现。把时间序列、分层结果和研究配置一起保留，至少可以在复盘时继续追问：它是持续有效，还是对某一种市场状态特别敏感？

这里的重点不是追求一个好看的单一数值，而是让因子的稳定性、覆盖率、截面表现和研究处理过程都有位置可看。验证结果仍然只是研究记录，不是因子获利能力的证明。

### 因子代码和图表不应彼此失联

![因子代码与 IC 分析](media/02-因子代码与IC分析.png)

研究脚本可以在界面里查看和编辑，右侧紧接着展示同一次研究生成的 IC 图。这里展示的是因子研究脚本，而不是 ZiyuQuant 的应用工程源码。这样安排的原因很朴素：当一条曲线发生变化时，我不想再靠记忆猜测它究竟用了什么表达式、窗口和输入字段。

在本地工作流中，因子需要先声明它使用的输入字段与所需历史窗口；研究执行器只提供当前日及此前的数据。这样做不能自动保证一个因子正确，却能避免把“看到了未来数据”误当成研究结果。

### 因子多起来以后，先把状态和来源讲清楚

![因子大全与批量研究](media/03-因子大全与批量研究.png)

因子大全把不同来源的研究条目放在一起管理，并保留筛选、状态与批量研究入口。做这页并不是为了展示一个很大的因子数量，而是为了在因子逐渐增多后仍能回答几个基本问题：哪一个已经验证、哪一个仍在等待、哪一个因为输入数据不足而不能运行、哪一个结果需要重新检查。

对于个人研究来说，整理能力经常比“再新增一个表达式”更重要。一个因子的定义、当前版本和研究结论如果彼此分散，过一段时间以后很容易只剩下一个名字和一张脱离语境的图。

## 2. 策略回测：把研究价格和账户价格分别处理

### 策略脚本、净值、基准和回撤放在同一条叙事里

![策略代码与净值回测](media/04-策略代码与净值回测.png)

策略页左侧是研究策略脚本，右侧是策略净值、基准和回撤等结果。回测不只是把选股结果乘上一段收益率：信号、下单、成交、费用、现金、持仓和估值都有各自的时间点与规则。界面把脚本与结果并列，是为了在看曲线时可以同时回到它对应的研究逻辑。

我比较坚持的一点，是不要用同一套价格去简单地解决“做指标”和“算账户”两件事。研究中可以使用连续的研究价格；账户层面的成交、现金、持仓市值和费用，则应继续按账户口径计算。两者如果混在一起，图会显得更顺，却很难解释真实的执行假设。

### 拖动区间时，从同一个起点重新比较

![净值、基准与回撤导航](media/05-净值基准回撤导航.png)

净值图下方保留时间 Navigator。拖动左边界后，策略净值和基准都会以新的区间起点重新归一到 1；因此看到的不是原始全区间曲线被简单裁切，而是从所选起点开始的一次可比观察。最大回撤的发生区间也会在图上标识出来，方便把“最后收益是多少”转成“问题是从什么时候开始累积的”。

它不会告诉人策略一定好，也不会把回撤解释为一次简单的偶然事件；它只是让查看者更容易回到某一段具体时间，继续检查当时的持仓、订单和市场背景。

## 3. 模拟验证：把信号、预单、订单和持仓分开记录

### 三个隔离账户，对应三条互不污染的验证线

![模拟验证账户隔离](media/06-模拟验证账户隔离.png)

模拟验证提供三个相互隔离的本地账户。它们不是为了制造“多账户运营”的视觉效果，而是为了让不同的策略版本、研究想法或参数试验可以各自保留状态。不同账户的现金、持仓、订单、成交和运行历史不会混在一起，回看时也不必猜一笔交易究竟属于哪次测试。

这些账户是日频延迟回放环境，不连接券商、不发送真实委托，也不等同于实际清算或真实交易账户。

### 今天有信号，不等于今天已经成交

![模拟验证：明日预下单](media/07-模拟验证-明日预下单.png)

“明日预下单”专门保留信号日与预期成交日的差异。当日因子和策略信号生成后，系统会先记录下一交易日的预单；之后，只有在对应交易日的真实日线、交易状态与账户条件满足时，才会形成正式订单与成交记录。

这个过程能把很多容易被一笔带过的情况摊开：停牌或涨跌停导致的不可成交、现金不足、股票整手取整、价格变化带来的数量偏差，以及预单与最终订单不一致的原因。对我来说，这类差异不该被当作“回测的小误差”，而应该能被追溯。

### 净值变化后，继续追到具体持仓

![模拟验证：历史持仓与盈亏](media/08-模拟验证-历史持仓与盈亏.png)

历史持仓表把收盘价、持股数量、持股金额、单日盈亏、持有总盈亏和组合权重放在一起；相关列支持排序。单日盈亏与持有总盈亏均同时显示金额和百分比，目的是让一条总净值变化能够继续落到具体股票和具体日期。

这个页面不是用来强调某一只股票的盈亏，而是一个对账入口：当净值出现明显变化时，可以顺着持仓表判断是市场价格波动、仓位结构，还是某次订单与预单的差异造成的。

## 4. 模型研究：把训练约束和样本外结果留在同一个地方

![模型研究与滚动训练配置](media/09-模型研究与滚动训练配置.png)

模型研究页用于把已验证的因子接入滚动训练，并在同一处查看训练配置、模型脚本和样本外结果。对时间序列研究而言，最容易被忽略的并不是模型能不能拟合，而是训练窗口、验证方式、特征可见性和样本外区间是否被明确保留。

截图中的结果区保持“尚未运行”，这是当时的真实状态。本次展示没有为了得到一张更好看的图临时挑选因子或补跑模型。模型运行后，样本外 IC 与预测表现会作为研究记录留在页面里；它们仍然需要结合样本区间和配置解释，而不是直接转换成交易结论。

## 5. 市场情绪：为研究结果补一层可回看的背景

![市场情绪趋势看板](media/10-市场情绪趋势看板.png)

市场情绪页把多个观察方向的情绪分、趋势分与历史曲线放在时间轴中，也提供区间导航和悬停观察。它不是一个“今天该追什么题材”的信号机，更接近我研究时的背景板：当某段因子或策略结果异常时，可以先看看当时市场大致处在怎样的情绪和趋势状态。

市场情绪本身不被包装成确定性预测。它的作用是补充观察维度，帮助研究者提出更具体的问题，而不是替代风险控制或交易判断。

## 6. 数据与审计：结果至少要知道从哪里来

### 数据中心不公开数据，但公开数据边界

![数据中心与研究边界](media/11-数据中心与研究边界.png)

数据中心列出研究流程实际使用的组件，包括行情、动态股票池、财务、公司事件、股本、停复牌、ST/风险状态、交易状态与涨跌停限制等。页面会区分原始价格、后复权价格与辅助数据的角色，也会提示数据的覆盖范围和当前状态。

原始数据不会被上传到这个仓库。这里展示的是数据在研究流程中的位置，以及我如何避免把不同口径的字段混为一谈。比如，财务数据需要关心公告可见性；公司行为不能只靠复权价格“看起来已经处理过”；涨跌停和停复牌也不应在执行环节被简单忽略。

### 一次运行结束后，仍然应该能回看

![运行历史与结果审计](media/12-运行历史与结果审计.png)

运行历史保留研究区间、核心指标和状态，作为回看与对账的入口。对我而言，“已经跑完”不是一个足够完整的结论；过一段时间以后，至少仍应知道眼前的曲线、指标或账户状态属于哪一次运行、覆盖了什么区间、当时处于什么结果状态。

这并不意味着系统可以消除所有数据问题或研究偏差，但它让排查有一个开始的位置，而不是只留下一个最终数字。

## 当前范围与非目标

ZiyuQuant 当前有明确的边界：

- 面向 A 股**日频**研究，不支持实时行情、分钟线、Tick 级研究或高频交易；
- 模拟验证采用延迟日线回放，不连接券商，也不等同于真实账户清算；
- 不对截图里的历史回测、模拟账户或模型指标作收益承诺；
- 不提供源码、数据、策略包、应用二进制、在线服务或复现实盘环境；
- 研究结果会受样本区间、股票池、费用、信号生成时点、成交约束与数据口径影响，历史表现不代表未来。

## 如何阅读这组截图

如果只是想快速了解 ZiyuQuant，可以按下面的顺序看：

1. 从“因子研究”了解一个信号如何被定义、验证和管理；
2. 再看“策略回测”，理解研究价格、账户价格、净值和回撤如何放到同一个视图；
3. 接着看“模拟验证”，观察信号如何先形成预单、再变成正式订单和持仓；
4. 最后回到“数据中心”和“运行历史”，理解每次研究结果的来源和可回看边界。

对我而言，这个项目最有价值的部分不是把曲线画得多漂亮，而是在遇到收益差异、一次回撤或一笔没有成交的订单时，仍然可以从界面里慢慢查回去。量化研究中的许多细节看起来琐碎，却往往决定了一项结论究竟是可解释的研究结果，还是一条暂时好看的线。
